# Todoist-Inspired Flutter TODO App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a robust, test-driven Todoist-inspired Flutter task management application with local notifications, tab filters, search, and local persistence.

**Architecture:** Clean Layered Architecture (MVVM) separating Domain, Data, and UI layers using pure Dart functions for business logic and Flutter's built-in `ChangeNotifier` + `ListenableBuilder` for reactive state.

**Tech Stack:** Flutter 3.47.6 / Dart 3.13.5, `shared_preferences: ^2.5.4`, `flutter_local_notifications: ^19.0.0`, `timezone: ^0.10.0`, `flutter_timezone: ^4.1.0`, `permission_handler: ^12.0.1`, `intl: ^0.20.2`.

**Spec:** `docs/superpowers/specs/2026-10-06-todo-app-design.md`

## Global Constraints
- **UI Language:** English.
- **Target Platforms:** Android (`minSdkVersion 24`, Java 17, `coreLibraryDesugaring`) & iOS.
- **State Management:** Pure `ChangeNotifier` + `ListenableBuilder` (zero external state libraries).
- **Commit Standard:** Atomic Conventional Commits (`<type>(<scope>): <subject>` <= 72 chars, zero secrets).
- **Testing Standard:** All domain logic (`isOverdue`, `reminderTimeFor`, `visibleTodos`, `nextId`) must be 100% covered by pure unit tests.

## Review Focus
- [Failure mode 1: Stale relative date/overdue badge when app stays open across midnight] -> Covered in Task 7 (60-second ticker + lifecycle listener).
- [Failure mode 2: Collision of ID upon rapid delete and undo with new task creation] -> Covered in Task 7 (`undoDelete` ID collision check).
- [Failure mode 3: Data corruption wiping entire task history on app reload] -> Covered in Task 5 (record-by-record parsing & corrupt backup).
- [Failure mode 4: Duplicate notification alert upon editing task time] -> Covered in Task 6 (cancel before schedule).
- [Failure mode 5: Virtual keyboard obstructing form fields in add/edit sheet] -> Covered in Task 9 (`isScrollControlled: true` & `viewInsets` padding).

- [ ] **Step 1: Write failing unit tests for pure logic**
Create `test/domain/logic/todo_logic_test.dart` testing:
- `nextId`: empty list returns 1; list `[1, 5, 3]` returns 6.
- `isOverdue`:
  - Date-only task on same calendar day returns false (not overdue in morning).
  - Date-only task from yesterday returns true.
  - Timed task due 1 minute ago returns true.
  - Timed task due in 1 minute returns false.
  - Completed task returns false.
- `reminderTimeFor`:
  - Dateless / completed / `hasTime == false` returns null.
  - Past due date returns null.
  - Due in 30 mins returns `due - 10m`.
  - Due in 7 mins with `allowLate: true` returns `now + 5s`.
  - Due in 7 mins with `allowLate: false` returns null (anti-spam on startup).
  - Due in 3s with `allowLate: true` returns null (never alert after due date).
  - Parametric `leadTime: Duration(minutes: 1)` returns `due - 1m`.
- `visibleTodos`:
  - Today tab includes tasks due today AND overdue tasks from previous days.
  - Upcoming tab includes tasks due strictly from tomorrow.
  - All tab includes dateless tasks.
  - Completed tasks are excluded from all tabs.
  - Query filtering matches title or description case-insensitively within active tab.
  - Stable sort order: dated before dateless, then `dueDate` asc, then `createdAt` asc, then `id` asc.
- `countForFilter`: returns count unaffected by query.
